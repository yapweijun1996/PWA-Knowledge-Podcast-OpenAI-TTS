# UI internationalization

Simplified Chinese (`zh-CN`) is the source catalogue. English (`en`) and
Malay (`ms`) share its keys. The Settings language selector displays each
language in its own language.

The app uses a valid saved locale preference, then defaults to `zh-CN`.
This keeps the first visit and browser tests in Chinese even when the browser
prefers English. Navigator-based detection is a future option. A change applies
on the current page without reloading, updates the document's `lang`, and saves
only the locale code under `podcast-ui-locale` in the viewer's local storage.
When storage is unavailable, the choice applies for the lifetime of the page.
Episode content in a different language needs its own `lang` attribute.

## Add a message

1. Add a `[key, message]` entry to the matching area under
   `src/i18n/locales/zh-CN/`. Use a key such as `library.episodes.empty`.
2. Add the same key to the corresponding English and Malay modules. Use
   identical placeholder names across translations. Check terminology in the
   [UI glossary](../src/i18n/glossary.md).
3. In a React component, get `t` and `formatters` from `useI18n()`. For code
   outside React, import `t` from `src/i18n` to read the current locale. Use
   `t("some.area.message", { name: value })` for a message containing `{name}`.
   Keep full key literals in static maps when selecting a key dynamically so
   the unused-key check can find them.

Missing translations fall back to the Chinese message. If both catalogues
lack the key, the app displays a marker such as `⟦library.episodes.empty⟧`.
The catalogue tests check parity even when a fallback would display readable
text.

## Public errors

Give each user-facing shared or worker error a stable code. For example,
`new PublicError(message, 422, "edit.turnLength", { maximum })` keeps the
existing Chinese `message` and adds values for the locale's
`errors.edit.turnLength` message. Use plain strings or finite numbers in
`params`. Use app-defined values such as limits and indices.

The worker returns `{ error, code, params }` for failed HTTP requests and
stores `{ message, code, params }` on failed jobs and schedule checks. Extra
fields are optional for compatibility with older workers and episode backups.
In the UI, `translateError` resolves the code at render time and falls back
to the stored public message. Browser production checkpoints use the existing
`studio.production.*` keys. Map provider failures to public messages at the
provider boundary and omit provider bodies and exception stacks.

Mark consent, costs, billing, key risks, no-retry guidance and unknown paid
outcomes with `// native-review` in each locale.

## Not translated by design

- Web research and independent cross-check prompts in
  `shared/pipeline/research.ts` and `shared/pipeline/research-audit.ts`.
- Outline and dialogue prompts in `shared/pipeline/script.ts`, plus the
  language-specific script and narration directions in
  `shared/pipeline/languages.ts`.
- Automated topic selection in `server/production.mjs`, Realtime narration in
  `server/audio.mjs` and `src/factory/browser-narrator.ts`, and tool-use
  instructions in `src/agent/agent.ts`.
- Episode content such as titles, dialogue, sources, and transcripts follows
  the episode language.

## Plurals and formatting

Use a plural object for a counted message. Each locale must provide `other` and
can provide more forms from `Intl.PluralRules(locale)`. For example, English
can use `{ one: "{count} episode", other: "{count} episodes" }`. Chinese and
Malay use `other` for cardinal counts. Keep the same placeholder names in every
form. Call `t(key, { count })` or `formatters.plural(key, count)` with a finite
numeric count. Keep the whole phrase in each form so translators can choose
word order and inflection.

Use `formatters.dateTime(value, options)`, `formatters.number(value, options)`,
`formatters.relativeTime(value, unit, options)`, and
`formatters.list(values, options)` for locale-aware rendering. Number and
bigint interpolation values are formatted by the message's locale.

## Add a locale

1. Create the locale directory with the same area modules and keys as
   `zh-CN`. Import and register the modules in `src/i18n/catalogues.ts`.
2. Add the locale's own-language label to each Settings catalogue and map
   the new locale code to that key in `src/factory/Preferences.tsx`.
3. Add the glossary terms, include the locale in the Intl formatter checks,
   and exercise the Settings switch and persistence in the browser.

## Native review

Consent, cost, key-risk and no-retry text must receive native review before
machine-translated copy in those groups ships. The English process uses
team-authored copy and owner review. Malay remains unreviewed until a native
speaker checks the glossary and all four groups. Record the reviewer and date
in the [UI/UX standard](UIUX-STANDARD.md) before marking anything as reviewed.

## Checks

```sh
npm run typecheck && npm test
npm run i18n:scan
```

The scan counts CJK-containing string literals, JSX text and template fragments
in `src/**/*.ts` and `src/**/*.tsx` outside `src/i18n`. It prints per-file
counts and a total, and exits successfully when it finds matches. It excludes
comments and also counts literals used for non-UI data. T45 uses the count as
an extraction baseline and reviews the matches in context.
