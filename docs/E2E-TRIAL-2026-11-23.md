# First real end-to-end trial (2026-11-23)

One run of the whole browser-first path with the owner's own key, no worker.

## Setup

- App: the public build (`npm run build`, `vite preview`) at
  `http://127.0.0.1:4173/PWA-Knowledge-Podcast-OpenAI-TTS/`; no worker process.
- Browser: Playwright Chromium on macOS, English UI. The key was typed into
  Settings and held in page memory; the script read it from a local file outside
  the repository and redacted it from all output.
- Topic: 新加坡的组屋为何能容纳不同族群？ with "exactly two hosts" and the
  default production bounds (240 s maximum audio).
- Estimate shown before consent: about 51,928 output tokens, up to 11 web
  searches and about 240 seconds of transcription (a ceiling, labelled as an
  estimate). Actual dollar cost: **UNVERIFIED** (only token ceilings and call
  counts were observed; no price source was checked).

## Defects and polish found

1. The MP4 is large for a mostly static scene (about 2 Mbit/s). Target 8 to 15
   MiB for 2 minutes.
2. The title card and thumbnail wrapped a 15-character Chinese title leaving a
   single character on the last line.
3. Source links in the description carry `?utm_source=openai`.
4. The worker probe produces console 404 noise when no worker exists.

Items 1 to 3 are task T49.

## Not established

Listening quality and continuity, Safari and mobile, the YouTube upload itself
(Opus-in-MP4 acceptance), a long episode near the memory limits, behaviour with
a flaky network mid-run, and the real dollar cost.
